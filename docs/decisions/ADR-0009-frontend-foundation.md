# ADR-0009: Frontend foundation (routing, themes, design tokens, accessibility testing)

Status: Accepted by the owner on 2026-10-23 (decisions 1-3 of the frontend plan approval); the remaining choices were made within F0 and are recorded for review.

## Context
The frontend was a single page (sign-in plus the plans, runs and findings panels) on the Vite template's styles. The owner asked for the whole product UI under `docs/architecture/ui-ux-design.md`: monochrome, top navbar only, Light/Dark/System themes, accessible by design. F0 lays the shared foundation that F1-F9 build on. This ADR covers frontend work only and does not touch Stage 11.

## Decisions
1. **Routing: `react-router-dom` 7.** Owner decision. Every page, run, finding and evidence item gets a URL. `App` does not create its router: `main.jsx` provides `BrowserRouter`, tests provide `MemoryRouter`.
2. **Accessibility testing: `axe-core` plus `vitest-axe` (dev dependencies).** Owner decision. Automated checks catch structural problems only; colour contrast is checked separately by a test that computes WCAG ratios from `tokens.css`, because jsdom has no layout. Manual keyboard and screen-reader checks remain required (Q89).
3. **System font stack, no web fonts.** Owner decision: no font service, no extra dependency, nothing to load or block.
4. **Design tokens as CSS variables**, in `src/styles/tokens.css`. `data-theme` on `<html>` is always the *resolved* theme (light or dark), so only two token blocks exist. The user's choice (light, dark or system) is stored in `localStorage` under `sentinel-theme`; "system" removes the key and follows `prefers-color-scheme`, including live changes. An inline script in `index.html` applies the theme before first paint (no flash); it mirrors `src/theme/theme.js` (Q88). Storage failures fall back to system.
5. **No UI library.** Shared components are small and live in `src/components/`; styles use tokens only. Bare elements (button, input, table) are styled in `base.css` so the existing panels follow the theme without being rewritten.
6. **One status vocabulary** (`src/lib/status.js`) layered on the existing feature `labels.js` wording: every status has a label, a tone and an icon. Unknown values render neutral. Finished runs, approved plans and unverified findings are never shown as a success tone; infrastructure outcomes (could not start) are distinct from test failures.
7. **Error mapping** (`src/lib/errors.js`): 401/403/404/409/422 get their own kinds and safe wording; 5xx text from the server is not echoed.
8. **Navigation:** the navbar lists only routes that exist (`app/navItems.js`); page-level sections use `TabNav`. A developer-only component gallery at `/design-system` is compiled out of production builds (`import.meta.env.DEV`).
9. **Focus management:** a skip link, and focus moves to `<main>` on client-side navigation; dialogs trap focus, close on Escape and restore focus.

10. **File organization (owner requirement, 2026-10-23):** component- and page-based; pages in `src/pages/`, shared components in `src/components/`, hooks (including context-reading hooks) in `src/hooks/`, API client in `src/services/`; every component's CSS beside its JSX with the same base name; `src/styles/` holds only `tokens.css` and `base.css`. Written into `frontend/CLAUDE.md`. Side effect: a component's CSS is bundled only when some page imports the component.

11. **Routes and auth (F1-F4):** public `/`, `/signin`, `/request-access`; protected `/account`, `/approvals`, `/projects` and `/projects/:id/{setup,analysis,plans,plans/:planId,runs,findings}` behind `RequireAuth` (a usability redirect; the server authorizes every call). The sign-in `next` target is accepted only as a plain in-app path (`lib/safeNext.js`). A 401 on any protected API call (not sign-in or the session probe) signs the user out in the UI and returns them to sign-in with a "session ended" notice (`setUnauthorizedHandler` in `services/api.js`). The API client is provided once through `ApiContext` (`useApi`), so pages need no prop threading and tests supply a fake.
12. **Request Access** is informational (owner decision): accounts are created by an administrator; the page has no form and says it sends nothing. The overview page is composed from existing list endpoints (owner decision); each panel loads independently and says "none yet" rather than inventing a value.

13. **Sign-in and request-access pages (owner redesign, 2026-10-23):** a quiet editorial layout (`features/auth/AuthLayout`): serif headings from the **system serif stack** (`--serif`, no web fonts, so the system-font decision stands), a mono section tag, a floating card with two sheets stacked behind it, and a very faint grid with a few drifting test marks (`AuthBackdrop`; transforms only, off for reduced motion, hidden from assistive technology). These pages use a minimal top bar (brand and theme control) and no footer (`app/authPaths.js`). **There is no sign-up**: the API has no registration route (only an admin-only create-user route), so the "Sign up" page is the informational Request Access page and `/signup` redirects to it.

14. **Brand logo (owner, 2026-10-23):** the owner's shield "S" logo (`~/Downloads/Shield S-Tech Verification Logo.png`, left untouched) is used beside the product name in the navbar (including the quiet sign-in bar) and the footer, and as the favicon and touch icon. Derived files: `src/assets/brand/sentinel-logo-light.png` (original colours, transparent background, cropped square, 128 px) and `sentinel-logo-dark.png` (the near-neutral dark navy lightened so it shows on dark themes; teal and grey unchanged), shown by `components/BrandLogo` according to the resolved theme; `public/favicon-32.png` and `public/apple-touch-icon.png` (the logo on a white rounded tile so it shows on any browser theme). The logo is decorative (the name is always written next to it). The old Vite template favicon was removed.

## Consequences
- Existing behaviour is preserved; `PlansPage`'s loader moved to `hooks/useLoad.js` (its `error` is now the error object, with `errorMessage` for text). `FindingsPanel` and `RunsPanel` keep their own loaders until F5/F6.
- The Vite template stylesheet (`index.css`, purple accent, centred 1126px column) is removed.
- Reversible: tokens and components are isolated; the router and test libraries are standard.
